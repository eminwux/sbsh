# Verifying Release Artifacts

Every sbsh release (from the first release that includes this page onward)
publishes checksums, signatures, SBOMs and build provenance for its binaries
and container images. All signatures are keyless: they are made in GitHub
Actions with a short-lived [Sigstore](https://www.sigstore.dev/) certificate
bound to the release workflow, so there is no public key to download.

## What each release ships

| Asset                                      | Purpose                                                      |
| ------------------------------------------ | ------------------------------------------------------------ |
| `sbsh-<os>-<arch>`                         | The binary (`linux`, `darwin`, `freebsd` × `amd64`, `arm64`) |
| `sbsh-<os>-<arch>.sha256`                  | SHA-256 of that binary (used by `install.sh`)                |
| `SHA256SUMS`                               | SHA-256 of every binary                                      |
| `SHA256SUMS.sigstore.json`                 | cosign signature bundle for `SHA256SUMS`                     |
| `sbsh-<os>-<arch>.spdx.json`               | SPDX SBOM for that binary (generated by syft)                |
| `sbsh-<os>-<arch>.spdx.json.sigstore.json` | cosign attestation bundle linking the SBOM to the binary     |
| `sbsh-image-linux-<arch>.spdx.json`        | SPDX SBOM for the container image on that platform           |

The container image `ghcr.io/eminwux/sbsh` carries, by digest, a cosign
signature, an SPDX SBOM attestation per platform, and GitHub build provenance.

## Setup

The examples use [cosign](https://docs.sigstore.dev/cosign/system_config/installation/)
v3+ and the [GitHub CLI](https://cli.github.com/) (`gh attestation`).
Set the release you are verifying and the identity of the workflow that
signed it:

```bash
VERSION=v0.7.0   # the release tag you downloaded
IDENTITY="https://github.com/eminwux/sbsh/.github/workflows/release.yaml@refs/tags/${VERSION}"
ISSUER="https://token.actions.githubusercontent.com"
```

## Binaries

### Checksums

`install.sh` checks the per-asset `.sha256` automatically. To check a
manual download (stock macOS: use `shasum -a 256 -c` instead):

```bash
sha256sum --ignore-missing -c SHA256SUMS
```

### Signature

Verify that `SHA256SUMS` was signed by the sbsh release workflow. Once it
verifies, the checksum check above ties each binary to that signature:

```bash
cosign verify-blob \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER" \
  SHA256SUMS
```

### Build provenance (SLSA)

```bash
gh attestation verify sbsh-linux-amd64 --repo eminwux/sbsh
```

### SBOM

Verify the SBOM attestation for a binary, then inspect the SBOM itself:

```bash
cosign verify-blob-attestation \
  --bundle sbsh-linux-amd64.spdx.json.sigstore.json \
  --type spdxjson \
  --certificate-identity "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER" \
  sbsh-linux-amd64

jq '.packages[] | {name, versionInfo}' sbsh-linux-amd64.spdx.json
```

## Container image

### Signature

```bash
cosign verify \
  --certificate-identity "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER" \
  "ghcr.io/eminwux/sbsh:${VERSION#v}"
```

### Build provenance (SLSA)

```bash
gh attestation verify "oci://ghcr.io/eminwux/sbsh:${VERSION#v}" --repo eminwux/sbsh
```

### SBOM

Both platform SBOMs are attested to the multi-arch image digest. Each
SBOM records which per-platform manifest it was scanned from:

```bash
cosign verify-attestation \
  --type spdxjson \
  --certificate-identity "$IDENTITY" \
  --certificate-oidc-issuer "$ISSUER" \
  "ghcr.io/eminwux/sbsh:${VERSION#v}" \
  | jq -r '.payload' | base64 -d | jq '.predicate.name'
```
